# Run 的身分是檔案系統路徑，不是 ckpt_dir

每個 Run 的 args 裡都記了訓練當下的輸出路徑 `ckpt_dir`，看起來像是天然的識別碼。
它不是：在 81 個 Run 中有 60 個的 `ckpt_dir` 與實際位置不符，
因為 Filing（事後人工搬移資料夾）發生在訓練結束之後。所有工具一律以實際路徑識別 Run。

## Consequences

`ckpt_dir` 仍應讀取並保留，但只作為「訓練當下在哪裡」的歷史紀錄，
不得用於尋找檔案、比對身分或去重。`ckpt_dir` 與實際路徑的差異反而是有用訊號：
它精確地指出哪些 Run 被 Filing 過、從哪裡搬到哪裡。

### 唯一的例外：標註的重新對應

星號與附註（Note）以 Run 的路徑為 key 儲存，而 Filing 會改變路徑，使既有標註失去對應。
因此只在「路徑找不到對應 Run」時，退而以資料夾名稱重新對應 —— 僅限名稱在範圍內唯一的情況；
對應成功後標註一律改存到實際路徑之下，名稱不唯一或找不到則保留為孤兒，不做猜測。
資料夾名稱只用來修復過時的 key，不作為 Run 的身分。移除這個退路會讓所有被 Filing 過的 Run 的標註靜默失效。
